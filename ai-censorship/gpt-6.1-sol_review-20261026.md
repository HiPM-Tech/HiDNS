# UserToken 服务与操作权限变更审查

- 日期：2026-10-26
- 模型：openai/gpt-6.1-sol
- 范围：本次后端权限结构、签发与更新接口、认证执行点、历史数据迁移，以及相应测试和 API 文档。不是全仓库全面审查结论。

## 审查结论

本次变更范围内未发现未解决的 P0 / P1 问题。

### 权限边界

- `allowed_services` 使用服务到权限数组的对象；创建和更新拒绝未知服务、未知权限、旧数组和错误类型。
- 显式空对象和 DNS 空权限数组不会回退成全权限；MCP 仅支持 `["*"]`，没有引入新的 MCP 工具认证方式。
- DNS 操作权限在 `authMiddleware` 成功验证 UserToken 后、业务处理前执行；覆盖 Bearer 和 cookie 中的 UserToken。
- 权限按 Express 实际匹配的路由挂载前缀分类，记录子路由不会错误要求 `domains.read/write`；大小写、尾斜线和 HEAD 已覆盖。
- `records.write` 不隐含 `records.read`；令牌管理员角色不能绕过令牌操作权限。现有域名白名单和资源权限检查继续执行。
- JWT 身份不受 UserToken 操作权限约束；工作流原有 JWT 限制继续保留。

### 历史迁移与数据库分层

- 在所有非 dry-run DSM 初始化中执行迁移，包含已经使用 DSM 的旧实例，而不是仅处理 pre-DSM 遗留实例。
- 通过 BAL 专用函数按主键分页读取并更新，兼容数据库 JSON 返回字符串或对象的差异。
- `dns` / `mcp` 旧数组映射为各自 `["*"]`；旧全局 `*` 只展开到当前两个服务；已配置的新对象不被重新授权。
- 迁移可重复执行；权限读取仍兼容旧数组；损坏权限数据在验证时拒绝认证，不默认放行。
- SQLite 实际建库、dry-run、再次初始化、持久化迁移和权限收紧后的重复初始化已验证。未运行真实 MySQL / PostgreSQL 实例集成测试。

### 审查中修复的问题

- 原更新逻辑在省略 `start_time` / `end_time` 时也写入 `null`，仅编辑权限就可能删除原有效期限制。已改为未传时保持原值，显式清空才删除时间限制，并补充回归用例。

## 前端接续审查：整行可展开服务标签

### 范围与结论

审查范围为 `client/src/features/tokens/` 的类型、创建与编辑弹窗、服务选择器、列表展示与回归测试。本次范围内未发现未解决的 P0 / P1 问题。

- DNS、MCP 各占一整行；服务开关和展开按钮为独立按钮，展开不改变授权。
- DNS 子权限使用可切换的小标签，使用后端支持的 DNS 权限清单，不混入工作流内部的额外动作权限。
- 已启用服务没有选中具体权限时使用 `["*"]`；取消最后一项也恢复通配权限，并在界面显示说明。
- 未启用服务的 DNS 子权限按钮禁用；取消服务后移除键。MCP 只支持 `["*"]`。
- 创建、编辑显式提交对象；两个服务均关闭时提交 `{}`，不通过省略字段触发后端全权限默认值。
- 编辑正确回填通配、细粒度和无权限配置；空对象和 `dns:[]` 不会默认开启 DNS。
- 列表使用对象结构渲染服务徽标，权限内容通过标题展示；无权限时明确显示「无服务权限」。
- 展开控件包含 `aria-expanded` / `aria-controls`，服务与权限按钮包含 `aria-pressed`；弹窗设置最大高度与滚动，避免展开后超出视口。
- 编辑显式清空时间限制时提交 `null`，匹配后端的字段更新语义。
